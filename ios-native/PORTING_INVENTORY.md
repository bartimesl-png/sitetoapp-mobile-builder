## Professional and personal spaces

The native app already contains role selection and dashboard data paths for particuliers, real-estate professionals, brokers, artisans, diagnosticians, service providers, and seasonal hosts. The prior implementation also added professional demand queues (main/secondary postal code, radius, and department), accepted-demand contact visibility, a three-claim limit, mini-site requests, estimation requests, property-contact requests, and imported property controls. Department priority now considers departments for the professional’s secondary postal codes too, and the accept button prevents repeat taps while Wix processes a claim. Before a demand is claimed, contact and identity keys are recursively removed from the native available-demand payload, including nested Wix data; the accepted-demand payload remains available to the claiming professional. Particulier dashboard details load photo fields through `photo20`, include `photo1`, and deduplicate repeated image URLs. Native listing editing can now remove existing photos and add new ones from the iOS photo library; the server verifies ownership of every retained or newly uploaded image before updating the Wix CMS gallery. Seasonal hosts can now create, edit, and conditionally delete their accommodation records natively; the server verifies ownership and prevents deleting accommodations with linked bookings, reservations, rates, or calendar entries. Core property, guest-capacity, amenities, price, arrival, and access fields are editable; photos remain intact on edit but photo upload/removal and the complete site geocoding workflow are not ported.

Still to audit against every Wix route and role: each dashboard card/action, every profile field and validation rule, reviews, subscription and payment screens, customer-side messaging and attachments, referral flows, all push/email triggers, and any role-specific creation/moderation workflows. Real-estate professionals and seasonal hosts can read and answer their existing Wix conversations natively. Seasonal hosts can now accept/refuse pending booking requests; acceptance writes a confirmed Wix reservation and reserves the request's calendar rows, while refusal restores those rows to available. Both transitions verify that the request belongs to the signed-in host, check date conflicts, and use the existing Wix notification-email endpoint. Host availability can be edited natively by date, including blocking/unblocking, nightly-price override, and minimum stay; reserved, external, and pending-request dates are protected. Broker, artisan, diagnostician, and service-provider inquiries remain role-specific lead records with contact details rather than a shared native conversation inbox. Profile edits now use a dedicated native save action across the supported account roles; the server checks the signed-in member’s loaded profile ID before writing the role-specific Wix record. Professional edits preserve the existing Wix category and subcategory list when changing the primary activity. The artisan/diagnostician dashboard now resolves its Wix account/profile collections correctly, but its full site-specific dashboard action set remains to be audited. This inventory is not a claim that those surfaces are complete.
