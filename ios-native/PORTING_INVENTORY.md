## Professional and personal spaces

The native app already contains role selection and dashboard data paths for particuliers, real-estate professionals, brokers, artisans, diagnosticians, service providers, and seasonal hosts. The prior implementation also added professional demand queues (main/secondary postal code, radius, and department), accepted-demand contact visibility, a three-claim limit, mini-site requests, estimation requests, property-contact requests, and imported property controls. Department priority now considers departments for the professional’s secondary postal codes too, and the accept button prevents repeat taps while Wix processes a claim. Before a demand is claimed, contact and identity keys are recursively removed from the native available-demand payload, including nested Wix data; the accepted-demand payload remains available to the claiming professional. Particulier dashboard details load photo fields through `photo20`, include `photo1`, and deduplicate repeated image URLs. Native listing editing can now remove existing photos and add new ones from the iOS photo library; the server verifies ownership of every retained or newly uploaded image before updating the Wix CMS gallery. Seasonal hosts can now create, edit, and conditionally delete their accommodation records natively; the server verifies ownership and prevents deleting accommodations with linked bookings, reservations, rates, or calendar entries. The native form resolves and saves commune coordinates when the lookup succeeds. Core property, guest-capacity, amenities, price, arrival, and access fields are editable. Host photos can now be added or removed with the native picker; uploads use the app’s owner-scoped storage path, and the server only accepts URLs already attached to that owned Wix accommodation or uploaded for the signed-in host. The native form resolves commune coordinates from the postal code using geo.api.gouv.fr and stores latitude/longitude in the existing Wix accommodation record when available.

Still to audit against every Wix route and role: each dashboard card/action, every profile field and validation rule, reviews, subscription and payment screens, customer-side messaging and attachments, referral flows, all push/email triggers, and any role-specific creation/moderation workflows. Real-estate professionals and seasonal hosts can read and answer their existing Wix conversations natively. Seasonal hosts can now accept/refuse pending booking requests; acceptance writes a confirmed Wix reservation and reserves the request's calendar rows, while refusal restores those rows to available. Both transitions verify that the request belongs to the signed-in host, check date conflicts, and use the existing Wix notification-email endpoint. Host availability can be edited natively by date, including blocking/unblocking, nightly-price override, and minimum stay; reserved, external, and pending-request dates are protected. Broker, artisan, diagnostician, and service-provider inquiries remain role-specific lead records rather than a shared native conversation inbox. Their cards now offer native e-mail and phone actions when contact fields are available, alongside the existing mark-as-read action. Profile edits now use a dedicated native save action across the supported account roles; the server checks the signed-in member’s loaded profile ID before writing the role-specific Wix record. Professional edits preserve the existing Wix category and subcategory list when changing the primary activity. The artisan/diagnostician dashboard now resolves its Wix account/profile collections correctly, but its full site-specific dashboard action set remains to be audited. This inventory is not a claim that those surfaces are complete.
